How a change travels from an idea to the user’s screen

Steps 1 to 4: on the engineer’s PC and on GitHub

1 · Idea

The engineer decides what the tool should do next

2 · Build

Claude writes the code and runs the tests on the engineer’s PC

3 · Review

The engineer reviews the change and saves it to GitHub

4 · Check and build

GitHub runs every test and builds the Windows and Mac installers

Steps 5 to 7: nobody touches a user’s computer

5 · Release

The engineer marks a numbered release; GitHub publishes it

6 · Notice

The app checks GitHub when it starts, downloads the update, checks its signature

7 · Install

The new version installs on the next start; the user sees the change

If a test fails

The change goes back to step 2. Nothing reaches a user.

Claude and GitHub on the Simulation Tool · 5

Steps 1 to 4 happen on the engineer’s PC and on GitHub. Steps 5 to 7 run on their own: the app notices the new release, checks its signature and installs it on the next start. A failed test at step 4 stops the release.
