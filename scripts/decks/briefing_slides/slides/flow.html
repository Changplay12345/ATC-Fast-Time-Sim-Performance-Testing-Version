How a change travels from an idea to the user’s screen

Steps 1 to 4: on the engineer’s PC and on GitHub

1 · Idea

The engineer decides what comes next

2 · Build

Claude writes the code and runs the tests

3 · Review

The engineer checks it and saves it to GitHub

4 · Check and build

GitHub tests it and builds the installers

Steps 5 to 7: nobody touches a user’s computer

5 · Release

The engineer marks a numbered version

6 · Notice

The app finds the update and checks its signature

7 · Install

It installs on the next start

If a test fails

Back to step 2. Nothing reaches a user.

Claude and GitHub on the Simulation Tool · 7

Steps 1 to 4 happen on the engineer’s PC and on GitHub. Steps 5 to 7 run on their own: the app notices the new release, checks its signature and installs it on the next start. A failed test at step 4 stops the release.
