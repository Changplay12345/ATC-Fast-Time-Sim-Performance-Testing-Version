Should we finish the software before choosing a server?

Yes. Finish the software first and keep the server decision cheap and open until real users have run it.

Why software first

  • The right server depends on how much the tool gets used, and nobody knows that yet. Today's load numbers come from tests, not from real users. The finished app has a built-in load meter so we can read the real figure later.
  • The simulation is cheap to run. A 1,000-flight run takes about 10 seconds on an ordinary 8-core PC and under 2 GB of memory. Nothing about that forces a hardware purchase now.
  • The full version will change the numbers. Every feature added changes how much computing each run needs, so any sizing done today would be redone anyway.
  • Users judge the software, not the server. Features and correctness are what the testers see.

Keeping the server decision cheap

  • The desktop app needs no server. Testers keep using it whatever we decide later.
  • Several people on one PC already works over the office network, at no cost.
  • If a remote demo is wanted early, the cloud option costs about THB 720 a month, starts in an afternoon, and can be cancelled. It is a trial, not a commitment.
  • No hardware purchase yet. The server shortlist is ready for when real usage says a dedicated machine is worth it. Prices do not rise by waiting.

Suggested order

  1. Build the complete version using everything learned from the test version.
  2. Put it in front of the real users on desktop, plus the cheap cloud trial if a remote demo is wanted.
  3. After about a month of real use, read the load meter and the cloud bill.
  4. Then choose cloud, rented rack space, or an office server, with evidence. The proposals for each option will be ready for that meeting.

The trade-off: the server question stays open for a few months. In return, when it is answered, it is answered with real usage data and the smallest possible spend.
